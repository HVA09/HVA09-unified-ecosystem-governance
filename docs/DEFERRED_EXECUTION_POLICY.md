# سياسة تأجيل التنفيذ الذي يحتاج جهازاً أو اشتراكاً

- **التاريخ:** 18 نوفمبر 2026
- **النطاق:** جميع مسارات البرنامج الخمسة والمشاريع التابعة لها.
- **الحالة:** قاعدة تشغيل مقترحة؛ لا تغيّر ترتيب الأولويات أو تعريف الحزم.

## 1. المبدأ

نُبقي كل مهمة جاهزة من ناحية التصميم والتحضير، ونؤجل فقط خطوة التنفيذ أو التحقق التي تتطلب مورداً غير متاح حالياً، مثل كمبيوتر محلي أو جهاز اختبار أو حساب مدفوع أو رصيد API. عدم توفر المورد ليس سبباً لإلغاء المهمة أو إسقاطها أو تحويلها تلقائياً إلى Blocked.

## 2. تصنيف بوابة التنفيذ

| التصنيف | المعنى | ما يمكن إنجازه الآن | ما يؤجل |
|---|---|---|---|
| READY-NOW | لا يحتاج جهازاً محلياً أو اشتراكاً مدفوعاً | مراجعة المستودعات، التوثيق، التصميم، تعديلات GitHub منخفضة المخاطر، الاختبارات المتاحة مجاناً | لا شيء إلا إذا ظهر اعتماد جديد |
| DEFER-COMPUTER | يحتاج كمبيوتر المستخدم أو بيئة محلية/جهازاً فعلياً | تجهيز الأوامر والسكريبتات وخطة الاختبار ومعايير القبول، ومراجعة الكود عن بعد | التشغيل المحلي، محاكاة الأجهزة، اختبار الهاتف الفعلي، استعادة نسخة محلية |
| DEFER-PAID | يحتاج خطة مدفوعة أو رصيد خدمة/نموذج | تجهيز التكامل، إعدادات اختيارية، حدود التكلفة، اختبارات بديلة مجانية، وخطة تفعيل | شراء الخطة أو استهلاك الرصيد أو تشغيل المورد المدفوع |
| DEFER-BOTH | يحتاج جهازاً محلياً ومورداً مدفوعاً معاً | تجهيز التصميم والتهيئة غير السرية وخطة التنفيذ والتراجع | التنفيذ الفعلي حتى توفر الشرطين |

يجب تسجيل اسم المورد المطلوب بدقة. لا نفترض أن كل خدمة أو اختبار يحتاج اشتراكاً؛ نتحقق أولاً من وجود مسار مجاني أو Sandbox رسمي مناسب.

## 3. معنى «جاهزة ومؤجلة»

- تُحفظ المهمة بحالتها الموضوعية (Ready أو In Progress) مع وسم بوابة التنفيذ، ولا تُسجل Done بسبب اكتمال الوثائق.
- لا تُسجل Blocked لمجرد أن المستخدم لا يملك كمبيوتراً أو اشتراكاً الآن؛ تستخدم Blocked فقط عند وجود عائق فني/اعتمادي يمنع حتى التحضير أو عند فشل شرط قبول.
- يجوز استكمال العمل التحضيري المجاني: المتطلبات، التصميم، مراجعة الكود، scripts، test cases، بيانات الاختبار الاصطناعية، معايير القبول، وخطة rollback.
- تُفصل الأدلة: «تحضير مكتمل» ليس «تشغيل ناجح»، ونجاح CI ليس قبولاً على هاتف أو استعادة Backup أو Sandbox خارجي أو اختبار حمل.
- عند توفر المورد، تُستأنف المهمة من آخر نقطة موثقة دون إعادة العمل، ثم تُنفذ الاختبارات المطلوبة وتُسجل الأدلة قبل تغيير الحالة إلى Done.

## 4. ضوابط المال والأمان

- لا تنشئ اشتراكاً، ولا تشتري خدمة، ولا تفعّل تجربة مدفوعة، ولا تستهلك API credits أو موارد فوترة نيابة عن المستخدم.
- لا تنشر بيانات أو أسرار أو نسخ قواعد بيانات إلى خدمة خارجية بغرض تجاوز غياب البيئة المحلية.
- لا تخفّض معايير الأمان أو الجودة لاستبدال اختبار فعلي مطلوب بمحاكاة غير مكافئة.
- البدائل المجانية مقبولة فقط إذا كانت تحقق الغرض نفسه وتوثق حدودها؛ وإلا تبقى المهمة جاهزة ومؤجلة.
- لا تغيّر صلاحيات الإنتاج أو سياسات الاحتفاظ أو قواعد البيانات أو مفاتيح التكامل دون مسار موافقة مناسب.

## 5. سجل الجاهزية

لكل مهمة مؤجلة، يسجل سجل المهام:
1. معرف المهمة والمستودع المسؤول.
2. وسم البوابة: READY-NOW / DEFER-COMPUTER / DEFER-PAID / DEFER-BOTH.
3. المورد الدقيق المطلوب وسبب الحاجة إليه.
4. التحضير المجاني المنجز وما تبقى منه.
5. خطوات الاستئناف وأدلة القبول المطلوبة.
6. هل يوجد بديل مجاني مكافئ أم لا.

## 6. قاعدة الدفعات

تظل قاعدة الحد الأقصى خمس مهام صغيرة/متوسطة عبر البرنامج كله نافذة. يمكن أن تحتوي الدفعة على تحضير مجاني لمهمة مؤجلة، لكن لا تُحسب خطوة التنفيذ الخارجي غير المنفذة كإنجاز. لا تُسحب مهمة مؤجلة من السجل ولا تتجاوز ترتيب التبعيات لمجرد انتظار المورد.

## 7. أمثلة إرشادية

- اختبار Lumen على Moodle/Canvas Sandbox: تجهيز إعدادات الاختبار وحالاته الآن؛ تأجيل تجربة المنصة الخارجية إذا تطلبت حساباً أو بيئة غير متاحة.
- استعادة SQLite v8 محلياً في ERP: تجهيز تعليمات الاستعادة والتحقق الآن؛ تأجيل تشغيلها على كمبيوتر المستخدم.
- اختبار الهاتف والاتصال البطيء: إعداد السيناريوهات وقائمة القبول الآن؛ تأجيل القبول الفعلي على الجهاز.
- اختبار استعادة Backup أو حمل إنتاجي: إعداد الخطة والقياسات والبيئة الآمنة الآن؛ تأجيل التنفيذ الذي يحتاج بيئة/موارد غير متاحة.
- نماذج AI أو API مدفوعة: تصميم Model Gateway وحدود الاستخدام واختبارات mocks الآن؛ تأجيل تشغيل النموذج المدفوع أو شراء الرصيد.

هذه أمثلة لتصنيف بوابة التنفيذ، وليست إعلاناً بأن كل هذه المهام جاهزة تقنياً أو أن متطلباتها قد تحققت.
