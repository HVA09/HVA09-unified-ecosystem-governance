# المرجع الرئيسي للمنظومة التقنية المتكاملة

- **الإصدار:** 1.0
- **تاريخ الإنشاء:** 16 نوفمبر 2026
- **الحالة:** مرجع معتمد للتخطيط والحوكمة؛ ليس تفويضاً لتغيير الإنتاج أو دمج الشيفرة تلقائياً.
- **المالك:** المستخدم

## 1. القرار الاستراتيجي المعتمد

اعتماد برنامج هندسي موحد يتكون من خمسة مسارات مترابطة:

1. **Lumen** — المنصة التعليمية.
2. **AI Chat App** — تطبيق المحادثة الذكي.
3. **ERP** — نظام تخطيط موارد المؤسسات متعدد الشركات.
4. **AI Core** — نواة ذكاء اصطناعي مفتوحة الأوزان، مع وكلاء متخصصين.
5. **Unified Ecosystem** — طبقة التكامل والحوكمة المشتركة.

تُؤجَّل **المرحلة السادسة: الابتكار والتوسع** (المختبرات والمحاكيات والبحث والتطوير وأدوات بناء المشاريع والتقنيات الجديدة) إلى ما بعد استقرار المسارات الأساسية الخمسة.

هذا برنامج رئيسي واحد لتنسيق التوافق، وليس مشروعاً واحداً يدمج المستودعات أو قواعد البيانات أو دورة الإصدارات.

## 2. المبادئ المعمارية غير القابلة للتجاوز

- لكل منتج مستودعه، وفروعه، وإصداراته، وخط CI/CD الخاص به.
- تبقى قواعد بيانات Lumen وAI Chat App وERP منفصلة. لا مشاركة مباشرة للجداول أو قواعد البيانات بين المنتجات.
- يتم التواصل عبر واجهات API وعقود تكامل وإصدارات موثقة، مع مصادقة وتفويض واضحين.
- لا يعتمد تشغيل أي منتج على توفر منتج آخر؛ تعطل AI Core أو طبقة التكامل لا يجوز أن يعطل الوظائف الأساسية للمنتجات.
- تُعزل بيانات الشركات داخل ERP، ويجب اختبار العزل ومنع الوصول الأفقي بين الشركات.
- لا تُنقل بيانات المستخدمين أو الطلاب أو المؤسسات بين المنتجات إلا لغرض محدد ومصرح به وبأقل قدر لازم.
- تُحفظ النسخ الأصلية، وتُفضّل التغييرات الصغيرة القابلة للعكس.
- الأولوية للأدوات والخطط المجانية حالياً، ولا يُنشأ التزام مالي دون موافقة صريحة.
- لا أسرار أو مفاتيح أو بيانات إنتاج حساسة في المستودعات أو تقارير الاختبار.

## 4. المسارات الخمسة ونطاقها

### 4.1 Lumen — أولوية العمل الحالية

**الهدف:** إكمال واستقرار وظائف المنصة التعليمية وتجربة الطالب والمدرس والإدارة، مع الأمن والاختبارات والتشغيل.

**نطاق العمل:** إدارة المستخدمين والصلاحيات، المقررات والدروس والمحتوى، الواجبات والاختبارات والتقييمات، تقدم الطلاب والتقارير، تجربة الهاتف، الأداء، الأمن، النسخ الاحتياطي والمراقبة.

**قيد مهم:** لا يتوقف تطوير الوظائف الأساسية بسبب تأجيل Moodle/Canvas Sandbox. يظل تكامل LTI/AGS مساراً مستقلاً، ولا يُعلن جاهزاً للإنتاج قبل إكمال بوابات التحقق الخارجية.

**الحالة المعروفة عند إنشاء الوثيقة:** PR #154 في `HVA09/lumen-learning-platform` على الفرع `feat/lti-ags-rebased-20261115`، والحالة Open + Draft + Unmerged. آخر SHA موثق: `6c93b49c976245b778800ed63046a2aef321fbb9`. آخر CI موثق: run `43779761820` بنتيجة 4/4 نجاح، و521 اختبار Backend ناجح، و90% تغطية، وRuff بلا تشخيصات. اختبارات Moodle وCanvas Sandbox لم تُنفذ بعد؛ لذلك تبقى بوابة خارجية مفتوحة. يجب إعادة التحقق من الحالة الحية قبل أي تغيير أو قرار دمج لاحق.

### 4.2 AI Chat App

**الهدف:** تثبيت خط الأساس أولاً، ثم التطوير دون المخاطرة بالاستقرار.

**نطاق العمل:** إصلاحات الاعتمادية وتجربة المحادثة والملفات والرسائل والأدوات، الاختبارات، المراقبة والنسخ الاحتياطي. يبقى مسار النماذج مفتوحة الأوزان لاحقاً ضمن AI Core ما لم يثبت سبب معماري لإجراء غير ذلك.

**قيد:** لا تُخلط فروع أو قرارات أو مهام هذا المشروع مع Lumen أو ERP.

### 4.3 ERP

**الهدف:** تطوير نظام متعدد الشركات يدعم قطاعات مختلفة مع عزل صارم لبيانات كل شركة.

**نطاق العمل المبدئي:** فحص النسخة الأصلية، خريطة الوحدات والاعتماديات، نموذج الصلاحيات والكيانات، حدود تعدد الشركات، اختبارات العزل، ثم خطة تحسين تدريجية.

**قيد:** لا تعديل قبل استلام النسخة وفحصها؛ تُحفظ نسخة أصلية غير معدلة، وتُستخدم فروع منفصلة.

### 4.4 AI Core

**الهدف:** نواة مستقلة قابلة لإعادة الاستخدام تخدم المنتجات الثلاثة، وتدعم نماذج مفتوحة الأوزان ووكلاء متخصصين.

**التخصصات المستهدفة:** البرمجة وهندسة البرمجيات، Linux، الشبكات، Cloud وDevOps، الأمن السيبراني، وتحليل الملفات والمعرفة والتعلم.

**المكونات المرشحة للتصميم:** Model Gateway، إدارة النماذج والمزودين، Agent Runtime، أدوات وصلاحيات، قاعدة معرفة/استرجاع عند الحاجة، تقييمات، سجلات ومراقبة، واجهات API وإصداراتها.

**قيد:** لا تُختار تقنية أو نموذج أو استضافة نهائية قبل مقارنة المتطلبات والتكلفة والموارد والخصوصية. لا تدريب مكلف أو اعتماد على GPU مدفوع دون موافقة منفصلة.

### 4.5 Unified Ecosystem

**الهدف:** ضمان التوافق والتشغيل البيني دون إلغاء استقلال المنتجات.

**نطاق العمل:** عقود API وإصداراتها، هوية موحدة تدريجياً عند الحاجة، التفويض ونطاقات الوصول، سجلات التدقيق، سياسات الخصوصية، مراقبة التكاملات، إدارة الإعدادات، حدود الأعطال، وإجراءات التعافي.

**قيد:** لا قاعدة بيانات مشتركة شاملة ولا اعتماد إلزامي على خدمة مركزية واحدة. يجب دعم التوافق الخلفي وخطة إيقاف/ترقية للإصدارات.

## 5. ترتيب التنفيذ والاعتماديات

1. مواصلة Lumen بوصفه الأولوية الحالية، مع فصل بوابات LTI الخارجية عن تطوير وظائف المنصة.
2. بعد تثبيت بوابات استقرار Lumen الأساسية، استكمال مراجعة واستقرار AI Chat App في مستودعه المستقل.
3. استلام ERP وفحصه وحماية نسخته الأصلية، ثم وضع خطة التطوير والتنفيذ المرحلي.
4. استخراج المتطلبات المشتركة من المنتجات الثلاثة، ثم تصميم AI Core على أساس احتياجات مثبتة.
5. تصميم وتنفيذ Unified Ecosystem تدريجياً عبر عقود تكامل مجرّبة، لا عبر ربط شامل دفعة واحدة.
6. لا تبدأ المرحلة السادسة إلا بعد اجتياز بوابات الاستقرار والتشغيل للمسارات الأساسية.

يجوز تنفيذ أعمال توثيق وتصميم غير معطِّلة بالتوازي، لكن لا يجوز أن تخلق اعتماديات تشغيلية أو تغييرات متعارضة بين المستودعات.

## 6. نظام إدارة المهام ومنع الضياع والتكرار

### 6.1 معرفات ثابتة

يُمنح كل عمل معرفاً فريداً لا يُعاد استخدامه:

- `GOV-xxx` الحوكمة والمعمارية المشتركة.
- `LUM-xxx` مهام Lumen.
- `CHAT-xxx` مهام AI Chat App.
- `ERP-xxx` مهام ERP.
- `CORE-xxx` مهام AI Core.
- `ECO-xxx` مهام Unified Ecosystem.
- `INNO-xxx` أعمال المرحلة السادسة المؤجلة.

### 6.2 حقول كل مهمة

كل مهمة جديدة يجب أن تحتوي على: المعرف، المشروع/المستودع، الوصف، سبب الحاجة، الحالة، الأولوية، التبعيات، معايير القبول، مخاطر التغيير، الملفات/المكونات المتأثرة، الفرع وCommit/PR إن وجد، نتائج الاختبارات، ودليل الإنجاز.

### 6.3 حالات المهمة

`Proposed` مقترحة؛ `Ready` جاهزة؛ `In Progress` قيد التنفيذ؛ `Blocked` متوقفة بسبب موثق؛ `Review` للمراجعة؛ `Verified` اجتازت التحقق؛ `Done` مكتملة بدليل؛ `Deferred` مؤجلة؛ `Rejected` مرفوضة مع سبب.

لا تتحول المهمة إلى `Done` بمجرد تعديل الشيفرة. يلزم دليل قبول واختبارات مناسبة، وتوثيق Commit/PR عند وجود تغيير برمجي.

### 6.4 فحص منع التكرار والتعارض

قبل بدء أي دفعة:

1. مراجعة سجل المهام والقرارات وGit/PR الحالي للمستودع المستهدف.
2. البحث عن مهمة أو PR يغطي النتيجة نفسها؛ إن وجد يُستكمل بدلاً من إنشاء نسخة مكررة.
3. التحقق من التبعيات والملفات المشتركة وتعارض الفروع أو الإصدارات.
4. تحديد حدود التغيير ومعايير القبول وخطة التراجع.
5. تنفيذ أقل تغيير آمن يحقق الهدف.
6. تشغيل الاختبارات ذات الصلة، ثم اختبارات التكامل/الأمن/البناء بحسب التأثير.
7. تحديث سجل المهمة والقرار والنتائج، بما فيها حالات الفشل والقيود.

## 7. سياسة دفعات «اكمل»

- «اكمل» تعني متابعة الدفعة التالية ذات الأولوية في الخطة المعتمدة، لا إعادة تنفيذ المهام السابقة.
- الهدف الافتراضي حتى خمسة مهام صغيرة أو متوسطة مترابطة في الدفعة الواحدة.
- الرقم خمسة سقف تنظيمي إرشادي، وليس وعداً بخمس مهام كبيرة أو بتغيير خمسة مستودعات في كل دفعة.
- يجوز إنجاز أقل من خمسة إذا كانت المهمة أكبر أو ظهرت بوابة جودة/أمان أو اعتماد مفقود.
- لا تُفتح تغييرات متعددة المستودعات في الدفعة نفسها إلا عند ضرورة معمارية واضحة، مع عقود وإصدارات واختبارات توافق.
- تقرير الدفعة يذكر: المهام ومعرفاتها، ما تغير، Commit/PR، الاختبارات ونتائجها، ما تعذر، المخاطر المتبقية، والدفعة التالية.

## 8. بوابات السلامة والجودة

- عدم تغيير `main` أو الإنتاج مباشرة.
- عدم تنفيذ migrations أو حذف أو تعديل بيانات إنتاج دون خطة وموافقة وإثبات نسخ احتياطي واختبار استعادة.
- عدم كشف الأسرار أو طلب مشاركتها في المحادثة أو تسجيلها في السجل.
- عدم استخدام بيانات طلاب أو شركات حقيقية في الاختبارات؛ استخدام بيانات اصطناعية/مجهّلة.
- لا merge أو تحويل PR إلى Ready for review بناءً على نجاح CI وحده إذا بقيت بوابات Sandbox أو مراجعات إلزامية مفتوحة.
- لا نشر إنتاج قبل مراجعة أمنية، وخطة rollback، ومراقبة، ونسخ احتياطي مختبر.
- يجب التحقق من الحالة الحية للمستودع والـPR والـCI قبل اتخاذ إجراء؛ الحالة المسجلة هنا لقطة زمنية وليست بديلاً عن الفحص الحي.

## 12. قاعدة تحديث هذا المرجع

بعد كل دفعة عمل، حدّث السجل بدلاً من إعادة إنشاء خطة موازية. لا تُحذف المهام المكتملة؛ تُحفظ مع دليلها. عند تغيير قرار سابق، أضف قراراً جديداً يوضح ما الذي استُبدل ولماذا، ولا تمحُ التاريخ. إذا لم تتوفر إمكانية تحديث هذا الملف مباشرة في بيئة العمل، صرّح بذلك وأنشئ نسخة جديدة مرقمة؛ لا تدّعِ أن المستودع أو نظام إدارة مهام خارجي قد تم تحديثه.
